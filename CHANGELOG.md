## [v0.4.0] - 2026-11-05

Release from the v0.3.3 milestone: agent instructions move to the `AGENTS.md` standard, uploads go through the backends with size limits and metadata stripping, data paths become configurable, and the runtimes and telemetry stack are upgraded (Node 24, Go 1.27, vitest 5, fastmcp 4, Grafana 13). Breaking: the budget presigned-upload endpoint `POST /transactions/receipt/upload-url` is removed. Take `alfheim-setup backup` before updating, because Grafana 13 migrates its storage on first start.

### Added
- Configurable data locations (#801): `ALFHEIM_DB_DATA_PATH`, `ALFHEIM_OBJECT_DATA_PATH`, `ALFHEIM_METRICS_DATA_PATH` and `ALFHEIM_LOGS_DATA_PATH` turn the PostgreSQL, RustFS, VictoriaMetrics and VictoriaLogs data from named volumes into bind mounts of absolute host paths; unset keeps the named volumes, so existing installs are unchanged. `alfheim-setup` takes them as flags (`--db-data-path`, ...) or environment variables and asks for them in the wizard, creates each directory with the owner its container needs (postgres 70, rustfs 10001, Victoria* root; mode 0700 for the first two), fails if one is not writable, warns when it is on the same filesystem as `/`, and keeps an earlier choice on a re-run. `scripts/test-prod-startup.sh --bind-mounts` runs the production smoke test with bind mounts and the smoke-test workflow does so in CI.
- `backend_shared.images.normalize_image` (#804): applies the EXIF orientation, strips all metadata (EXIF/GPS, ICC, XMP), caps the longest edge (default 2560 px), encodes WebP (alpha kept), accepts JPEG, PNG, WebP and HEIC, and refuses decompression bombs. Pillow and pillow-heif ship as the optional `images` extra of `backend-shared`; `budget-backend` opts in.
- How-to `storage-layout.md` (EN and DE, #807): where each data class lives and how it grows, the recommended disk layout, ZFS and Btrfs settings (and why not `nodatacow` for PostgreSQL), and the bounded Docker log configuration. Linked from the docs index, the deployment guide and the backup guide.
- Nested `AGENTS.md` files (#796) for every backend, frontend, `packages/shared`, `packages/backend-shared` and `tools/installer`. Stack conventions now live once in `docs/en/reference/conventions/{python-fastapi,go,nextjs-tailwind}.md`, the shared component and theme blueprints became the how-to [Extend the shared package](docs/en/how-to/extend-shared-package.md), and the new-app scaffolding guide is merged into the FDD tutorial. `.ai/stacks`, `.ai/blueprints` and `.ai/guidelines/new-app-scaffolding.md` are removed.
- Code comment convention (#798): `docs/en/reference/conventions/code-comments.md`. Ruff `D` rules (Google convention) and the `revive` `exported` rule for Go now run in `verify.sh` and CI, and `verify.sh --security` fails on `TODO`/`FIXME` without an issue reference. Every existing module, class and public function was documented (#823), so no baseline remains.

### Changed
- Agent instructions follow the `AGENTS.md` standard (#795): the root `AGENTS.md` holds every binding rule for all coding agents, `CLAUDE.md` only imports it, and `.ai/rules/{core,architecture,safety}.md` are removed. The rule that agents must append to `.ai/CONTEXT.md` after every change is dropped; the remaining `.ai/` files are marked for migration (#794).
- Retired `.ai/CONTEXT.md` (#797): the sprint log is dropped (git history and this changelog hold it), the per-app database invariants for shopping, pantry, maintenance, chores, chat and workout moved into `docs/en/reference/apps/<app>.md` and the German pages, and the `TESTING` and `OTEL_ENABLED` flags joined the environment variable reference.
- Removed the `.ai/` folder (#799). The quality-gate reference moved to `docs/en/reference/quality-gates.md`; the router map, persona workflows and the two-step "APPROVED" gate were dropped. `scripts/check-markdown-links.py` (also run by `verify.sh --security`) now fails if `.ai/` is tracked again.
- `postgres-core` stores new TOAST values with LZ4 (`default_toast_compression=lz4`) in the dev and prod stacks (#806). Existing rows keep pglz until rewritten. `scripts/verify-stack.sh` checks the setting.
- Telemetry stack upgrade, dev and prod on the same pinned tags (#777, #782): VictoriaMetrics v1.99.0 → v1.154.1, VictoriaLogs v0.25.0 → v1.51.1, OpenTelemetry Collector 0.100.0 → 0.163.2, Vector 0.39.0 → 0.60.0, Grafana 12.4.12 → 13.2.4. VictoriaLogs stays at v1.51.1 because v1.52 and later images contain no shell, which the compose healthcheck and the `up.sh` / `test-prod-startup.sh` wait steps rely on.
- Collector config: `service.telemetry.metrics.address` (removed upstream) became a `readers` Prometheus pull exporter, and the `otlphttp` exporters were renamed `otlp_http`. The config ships as a release asset, so `alfheim-setup update` replaces it together with the compose file.
- Upgrade note: Grafana 13 migrates dashboards and folders to unified storage on first start and a downgrade does not undo it. Take `alfheim-setup backup` before updating; to roll back, restore that backup.
- Node.js 22 → 24 LTS: `node:24-alpine` in every frontend Dockerfile, `node-version: 24` in all workflows, `@types/node` `^24` and the docs portal `engines` (#783). Dependabot ignores major bumps of `@types/node` so it stays on the runtime major.
- Go 1.26.10 → 1.27.3 everywhere at once (#778): `go.work`, all four `go.mod` files, the `go-version` pins in `go-ci.yml`, `release.yml` and `security-scan.yml`, the three Go service Dockerfiles and the Caddy `GOTOOLCHAIN` pin, so the images build with the same toolchain CI tests with.
- Frontend test tooling: vitest 4 → 5, `@vitest/coverage-v8` 4 → 5 and msw 2 → 3 across all workspace packages (#780). msw's `onUnhandledRequest` became `onUnhandledFrame`; `@testing-library/jest-dom` matchers are declared locally (`src/tests/jest-dom.d.ts`) because its vitest typings do not yet match vitest 5's two-parameter `Assertion`. The `asyncUtilTimeout` stabilisation stays, and every vitest config caps `maxWorkers` at 2 because full parallel `pnpm -r test` runs timed out under vitest 5 with the default.
- fastmcp 3.4 → 4.1 in every Python backend (`>=4.1.5`, #781). `backend_shared.mcp_middleware` now reads the per-request household context through `fastmcp.server.dependencies.get_http_request()` instead of the removed MCP SDK `request_ctx`. The `mcp_requires_role` decorator and `ensure_mcp_role`, duplicated in the chores, pantry and maintenance apps, moved to the new `backend_shared.mcp_permissions`.
- CI: the frontend gate now runs `next build` for every Next.js frontend (matrix job `production-build`), so build-only failures such as an import above a `"use client"` directive fail `ci-required` on pull requests (#784).
- CI: GitHub Actions majors in one change (#779), all SHA-pinned: `pnpm/action-setup` 4.4.0 → 6.1.0, `gitleaks/gitleaks-action` 2.3.9 → 3.0.0 (Node 24 runtime, no input changes), `docker/build-push-action` 6.19.2 → 7.4.0, `docker/login-action` 3.7.0 → 4.7.0 and `softprops/action-gh-release` 2.6.2 → 3.0.3.

### Security
- Budget receipts (#802) are uploaded to the backend (`POST /api/v1/budget/transactions/receipt`, multipart) instead of straight from the browser to RustFS: capped at `MAX_RECEIPT_UPLOAD_BYTES` (default 10 MiB, HTTP 413), only JPEG, PNG, WebP, HEIC and PDF by content (HTTP 400 otherwise), images normalised to WebP without metadata via `normalize_image`, and stored under a server-generated key. The presigned-PUT endpoint `POST /transactions/receipt/upload-url`, `S3StorageService.generate_presigned_upload_url` and the matching frontend code are removed; new i18n keys `receiptTooLarge` and `receiptInvalidType` exist in en/de/pl.
- Library manual upload (#803) reads the PDF in chunks up to `MAX_MANUAL_UPLOAD_BYTES` (default 50 MiB, HTTP 413 above it), rejects content that does not start with `%PDF-` (HTTP 400) and stores it under a server-generated object key instead of the client file name; replacing a manual deletes the old object. The reusable `read_bounded_upload` and `generate_object_name` helpers live in `backend_shared.storage`.
- Chat image attachments (#805) are normalised on upload: EXIF orientation applied, all metadata (EXIF/GPS) dropped, longest edge capped at 2048 px, re-encoded as JPEG (PNG when the image has transparency), images above 40 megapixels refused. Pure Go (`golang.org/x/image`), so the chat binary stays CGO-free (+0.4 MB). Stored attachments therefore may differ in type from the uploaded file.

## [v0.3.1] - 2026-10-29

> `v0.3.0` was tagged on 2026-10-23 but never published: the release pipeline's image vulnerability gate blocked it (certifi, authlib and dnspython in the Python images, npm inside the Node base image, an outdated Caddy build) and an emulated arm64 build hung. v0.3.1 contains everything listed for v0.3.0 plus those fixes; only `dashboard-backend`, `household-backend` and `chat-backend` were pushed as `v0.3.0`.
>
> The lists below collect every change since v0.1.0-beta.1, because v0.1.2 to v0.3.0 were cut without their own sections; those sections were added later as short summaries.

Release from the October 2026 project review: tenant isolation and role matrix across all apps, real Alembic migrations, backup and restore, the `alfheim_operator` role, a hardened gateway, CI and release pipeline, multi-arch images (linux/amd64 and linux/arm64), and fixes found by an end-to-end installer verification. Upgrading from v0.2.2 with `alfheim-setup update` takes a backup first, migrates every database and repairs `.env` (S3 endpoints, `DOCKER_SOCKET_GID`, new secrets).

- `alfheim-setup backup` and `alfheim-setup restore` (#690): one verified archive with a `pg_dumpall` (no TTY, `POSTGRES_USER` from `.env`), the RustFS media, `.env`, the Zitadel machinekey, the CA and Caddy PKI and the stack files, plus a SHA-256 manifest; retention keeps the newest N. `alfheim-setup update` takes a database and secrets backup before it changes anything and aborts if that fails (`--skip-backup` to override). - Go 1.26.10 everywhere (workflows, `go.work`, `go.mod`, backend images): fixes GO-2026-6809 in `crypto/x509`. CI pins the exact patch version because `setup-go` otherwise reuses the runner's cached 1.26.9.
- Budget transactions could reference another household's accounts, pots, plans and categories and change their balances (#675).
- Shopping personal lists were readable and writable by any user who knew the id; workout exercises of other households were readable via favorites and plans; maintenance filtered tenants in Python and failed open (#681).
- Pantry promoted every barcoded product into a global catalog visible to, and stuck for, every household (#676).
- Chat: bootstrap model blocks could be taken over by any user, leaking the operator API key and other users' prompts; outbound LLM URLs are now guarded against SSRF (`CHAT_ALLOWED_LLM_HOSTS`, dial-time checks, no redirects, no upstream bodies in client errors) (#680).
- Security headers on every gateway site (nosniff, Referrer-Policy, frame protection, report-only CSP, HSTS on secure installs) and no more reflective CORS in the dev gateway (#677).
- Frontend runner images no longer ship npm, npx, corepack and yarn (only `node server.js` runs there), which removes the HIGH findings in npm's bundled dependencies (brace-expansion, ip-address, pacote, picomatch, sigstore) that blocked the release image scan.
- pyjwt 2.15, mcp 1.30, urllib3 2.8, aiohttp 3.14.5; JWT validation runs off the event loop with a JWKS refresh cooldown and requires `exp`, `iat` and `sub`; error details are generic; default storage credentials and placeholder internal tokens are refused outside development (#678). `golang.org/x/text` 0.42 (#674).
- Go backends cap request bodies, accept only RS256 and fail closed without an authenticator; ADMINs can no longer manage other ADMINs; invite TTL and uses are bounded and tokens are stored hashed (#685).
- Zitadel self-registration is disabled during provisioning (#683); `init-env.sh` no longer falls back to a predictable secret and writes `.env` with `umask 077`.
- Release pipeline: least-privilege permissions, SHA-pinned actions (Trivy no longer `@master`), a blocking Trivy scan before images are pushed, and no `:latest` on pre-releases (#684).

Still open without an upstream fix: `http-cache-semantics` <=4.2.0 (GHSA-ch52-4w7c-c8xp, via Astro in the docs portal build) and `braces` <=3.0.3 (GHSA-vfj7-8cjw-p6xm, via `eslint-config-next` dev tooling). Both have no patched release and reach only build or dev tooling, never a production image; they are listed in `pnpm.auditConfig.ignoreGhsas` until a fix exists (#645).
  Tested: `pnpm audit` (7 advisories → 2 without a patched version); docs portal and landing builds; `./scripts/verify.sh --frontend`.
- Shared `OSMMapViewer` no longer renders marker popups or marker colors as HTML (#610). `popupContent` and the new `popupTitle` are set as text and `color` goes through the CSSOM, so a contact named `<img src=x onerror=…>` (or a crafted category color) cannot run script for household members who open a map, whichever app passes the data. The household frontend passes its data unescaped again and its `escapeHtml` helper is removed, so nothing is double-escaped.
- `backend_shared` binds every MCP session to the user and household that opened it (#633): a request on another caller's `Mcp-Session-Id` gets `403 household_forbidden`, and an unknown session id gets the MCP spec's `404`. All six MCP apps get this through `mount_mcp` without code changes.
- `X-Household-ID` no longer grants anything on its own: every backend, including chat, confirms the caller's membership with `core/household` and fails closed (`503`) when it cannot. This supersedes the interim chat rule that required a matching household claim.
- MCP tools can no longer be steered into another household by the LLM: the budget tools accepted `household_id` as an argument, and the other apps' tools derived households from arguments or hardcoded ids.
- Maintenance `/maintenance/wizard` and `/maintenance/summary` had no authentication, and the summary returned every household. Both now require a household member and are scoped to `X-Household-ID`.
- Chat attachments are restricted to their uploader. Migration `000003_add_image_ref_owner` adds `image_refs.owner_user_id`; reading another user's attachment returns `404`, and messages can only link unlinked attachments owned by the conversation owner (`400` otherwise). Attachments uploaded before the migration have no owner and can no longer be read by ID or linked.
